## 表结构总览

| 表名 | 用途 | 核心字段 |
|------|------|----------|
| users | 用户账户信息 | email, password_hash |
| knowledge_bases | 知识库元数据 | name, description, keywords |
| knowledge_docs | 知识库文档记录 | file_path, content_hash, status, chunk_count |
| sessions | 会话映射 | user_id, thread_id, title |
| feedbacks | 用户反馈评价 | user_id, message_id, rating, comment |
| checkpoints | LangGraph 对话状态（自动创建） | thread_id, checkpoint 数据 |
| checkpoint_blobs | LangGraph checkpoint blob 存储（自动创建） | thread_id, blob 数据 |
| checkpoint_writes | LangGraph checkpoint 写入（自动创建） | thread_id, 写入数据 |

## 表结构详述

### 1. users — 用户表

存储用户注册的账户信息。

```sql
CREATE TABLE users (
    id          INT             PRIMARY KEY AUTO_INCREMENT,
    email       VARCHAR(255)    NOT NULL UNIQUE,
    password_hash VARCHAR(255)  NOT NULL,
    created_at  DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at  DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,

    INDEX idx_users_email (email)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

**字段说明**：

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INT | 主键，自增 |
| email | VARCHAR(255) | 登录邮箱，唯一索引 |
| password_hash | VARCHAR(255) | bcrypt 哈希后的密码 |
| created_at | DATETIME | 注册时间 |
| updated_at | DATETIME | 更新时间 |

---

### 2. knowledge_bases — 知识库表

存储知识库的元信息，每个知识库对应 `knowledges/<name>/` 磁盘目录。

```sql
CREATE TABLE knowledge_bases (
    id          INT             PRIMARY KEY AUTO_INCREMENT,
    name        VARCHAR(100)    NOT NULL UNIQUE COMMENT '知识库名称，对应 knowledges/ 下的子目录',
    description TEXT            NULL     COMMENT '知识库描述',
    keywords    VARCHAR(500)    NULL     COMMENT '关键词，逗号分隔',
    created_at  DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at  DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,

    INDEX idx_kb_name (name)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

**字段说明**：

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INT | 主键，自增 |
| name | VARCHAR(100) | 知识库名称，唯一，对应磁盘目录名 |
| description | TEXT | 知识库描述，用于 Agent 判断路由 |
| keywords | VARCHAR(500) | 逗号分隔的关键词 |

---

### 3. knowledge_docs — 知识库文档表

记录上传到知识库的文档及其处理状态。

```sql
CREATE TABLE knowledge_docs (
    id                INT             PRIMARY KEY AUTO_INCREMENT,
    kb_id             INT             NULL     COMMENT '关联的知识库 ID',
    knowledge_base    VARCHAR(100)    NOT NULL DEFAULT '' COMMENT '知识库名称（冗余字段）',
    file_path         VARCHAR(500)    NOT NULL UNIQUE COMMENT 'knowledges/ 下的相对路径',
    original_filename VARCHAR(255)    NOT NULL COMMENT '原始文件名，前端展示用',
    file_size         INT             NOT NULL DEFAULT 0,
    content_hash      VARCHAR(64)     NOT NULL COMMENT '文件 MD5，用于重复检测',
    status            VARCHAR(20)     NOT NULL DEFAULT 'processing' COMMENT 'processing / ready / failed',
    chunk_count       INT             NOT NULL DEFAULT 0,
    error_message     TEXT            NULL,
    created_at        DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at        DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,

    INDEX idx_kd_kb_id (kb_id),
    INDEX idx_kd_status (status),
    INDEX idx_kd_hash (content_hash),
    CONSTRAINT fk_kd_kb FOREIGN KEY (kb_id) REFERENCES knowledge_bases(id) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

**字段说明**：

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INT | 主键，自增 |
| kb_id | INT | 外键，关联 knowledge_bases，级联删除 |
| knowledge_base | VARCHAR(100) | 冗余字段，方便查询时避免连表 |
| file_path | VARCHAR(500) | 磁盘上的完整路径，唯一 |
| original_filename | VARCHAR(255) | 用户上传时的原始文件名 |
| file_size | INT | 文件大小（字节） |
| content_hash | VARCHAR(64) | MD5 哈希，用于上传去重 |
| status | VARCHAR(20) | `processing` → `ready` / `failed` |
| chunk_count | INT | 分块后的块数 |
| error_message | TEXT | 处理失败时的错误信息 |

**状态流转**：

```
upload → processing → ready (成功)
                    → failed (失败)
```

### 4. sessions — 会话表

存储用户与 AI 的对话会话映射。

```sql
CREATE TABLE sessions (
    id          INT             PRIMARY KEY AUTO_INCREMENT,
    user_id     INT             NOT NULL COMMENT '用户 ID',
    thread_id   VARCHAR(64)     NOT NULL UNIQUE COMMENT 'LangGraph 线程 ID',
    title       VARCHAR(100)    NULL     COMMENT '会话标题（自动取用户首条消息）',
    created_at  DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at  DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,

    INDEX idx_sessions_user (user_id),
    INDEX idx_sessions_thread (thread_id),
    CONSTRAINT fk_sessions_user FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

**字段说明**：

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INT | 主键，自增 |
| user_id | INT | 外键，关联 users |
| thread_id | VARCHAR(64) | LangGraph 使用的线程 ID，用于从 checkpointer 恢复对话状态 |
| title | VARCHAR(100) | 会话标题，自动取用户首次提问的前 100 字 |

> **设计理念**：sessions 表仅存储轻量级的会话元数据（映射关系和标题）。完整对话消息记录由 LangGraph 的 AIOMySQLSaver 持久化到 `checkpoints` / `checkpoint_blobs` / `checkpoint_writes` 表中。

### 5. feedbacks — 反馈表

存储用户对 AI 回答的点赞/点踩评价。

```sql
CREATE TABLE feedbacks (
    id          INT             PRIMARY KEY AUTO_INCREMENT,
    user_id     INT             NOT NULL,
    message_id  VARCHAR(128)    NOT NULL COMMENT '被评价消息在 LangGraph Checkpointer 中的 UUID',
    rating      ENUM('like', 'dislike') NOT NULL COMMENT 'like=点赞, dislike=点踩',
    comment     TEXT            NULL     COMMENT '用户可选评价备注',
    created_at  DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP,

    INDEX idx_fb_user (user_id),
    INDEX idx_fb_message (message_id),
    UNIQUE KEY uq_user_message (user_id, message_id),
    CONSTRAINT fk_fb_user FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

**字段说明**：

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INT | 主键，自增 |
| user_id | INT | 外键，关联 users，级联删除 |
| message_id | VARCHAR(128) | 消息 UUID（来源于 LangGraph Checkpointer 中的消息 ID） |
| rating | ENUM('like','dislike') | 评价类型 |
| comment | TEXT | 可选文字反馈 |
| created_at | DATETIME | 评价时间 |

**联合唯一键**：`(user_id, message_id)` — 每个用户对每条消息只能有一条评价记录，切换 rating 时更新而非新增。

---

### 6. checkpoints 系列表 — LangGraph 状态持久化

这些表由 `langgraph-checkpoint-mysql[aiomysql]` 库自动创建和维护，存储完整的对话上下文。

**checkpoints 表**：保存每个 thread_id 在不同时间点的完整状态快照。

**checkpoint_blobs 表**：保存大块状态数据的二进制/文本 blob。

**checkpoint_writes 表**：保存并发写入的中间状态。

> 应用层无需直接操作这些表。通过 LangGraph 的 `AIOMySQLSaver` 进行读写。

## 关系说明

```text
users (1) ──→ (N) sessions     一个用户可以有多个会话
users (1) ──→ (N) feedbacks    一个用户可以有多条评价
knowledge_bases (1) ──→ (N) knowledge_docs  一个知识库包含多篇文档
sessions ──→ feedbacks         通过 message_id 逻辑关联（非外键约束）
```

## 与 Qdrant 的关联设计

系统采用 MySQL + Qdrant 双存储架构：

| 数据 | 存储位置 | 说明 |
|------|----------|------|
| 用户信息、会话元数据 | MySQL | - |
| 文档元数据（状态、哈希、路径） | MySQL | `knowledge_docs` 表 |
| 知识库信息 | MySQL | `knowledge_bases` 表 |
| 文档向量（嵌入） | Qdrant | payload 含 source, kb_name, section, content |
| 对话状态（消息历史） | MySQL | LangGraph checkpoints 系列表 |
| 用户反馈 | MySQL | `feedbacks` 表 |

**删除同步机制**：

- 删除文档 → 按 `source` 字段删除 Qdrant 向量 + 删除磁盘文件 + 删除 MySQL 记录
- 删除知识库 → 按 `kb_name` 字段批量删除 Qdrant 向量 + 删除磁盘目录 + 级联删除 MySQL 文档记录
- 删除会话 → 删除 MySQL sessions 记录 + 清理 LangGraph checkpoints

## 索引策略

| 表 | 索引 | 类型 | 用途 |
|----|------|------|------|
| users | email | UNIQUE | 登录查询 |
| knowledge_bases | name | UNIQUE | 创建时去重、Agent 路由查询 |
| knowledge_docs | kb_id | INDEX | 按知识库查询文档列表 |
| knowledge_docs | content_hash | INDEX | 上传时 MD5 去重 |
| knowledge_docs | file_path | UNIQUE | 防止同一文件重复处理 |
| knowledge_docs | status | INDEX | 按状态筛选（processing/ready/failed） |
| sessions | user_id | INDEX | 按用户查询会话列表 |
| sessions | thread_id | UNIQUE | LangGraph 按 thread_id 恢复对话 |
| feedbacks | user_id | INDEX | 按用户查询其所有评价 |
| feedbacks | message_id | INDEX | 按消息查询评价统计 |
| feedbacks | (user_id, message_id) | UNIQUE | 保证一用户对一消息仅一条评价 |
